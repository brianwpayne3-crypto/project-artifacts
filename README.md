# Project Artifacts

Public, intentionally shareable artifacts from projects I am building, operating, or exploring.

This repository is **not** the source repository for the underlying applications. Working code, operational data, customer information, internal issues, and implementation history generally remain in private project repositories.

The material here is selected for discussion, design critique, portfolio use, and collaboration.

## Projects

### Bucks County Bike Garage — Service Intake

An iPad-first bicycle service workflow built around the lifecycle of a customer-owned bicycle through intake, inspection, authorization, repair, quality control, handoff, payment, and closure.

- [Product information architecture](bcbg-service-intake/PRODUCT_IA.md)

The IA is intentionally product-facing rather than technical. It is meant to make the workflow and persistent information model understandable enough to critique before focusing on visual implementation.

## What belongs here

Good candidates:
- product and information-architecture diagrams;
- sanitized screenshots;
- design explorations;
- architecture diagrams intended for public discussion;
- project briefs and case-study material;
- selected prototypes or concepts.

Not appropriate:
- customer or personally identifiable information;
- secrets, credentials, private URLs, or production configuration;
- raw operational exports;
- material that exists only because the underlying private repo happens to contain it.

The rule is simple: **nothing becomes public here accidentally.**
